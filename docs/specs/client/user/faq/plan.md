# Plan: FAQ (Часті питання)

## Summary

FR-004 і FR-005 — серверна частина: редакційний контент у базі, локалізований,
один маршрут `GET /faq`. FR-001, FR-002 і FR-003 (картки, розгортання,
маркери) клієнтські: розгорнутість — стан екрана, а не дані.

## Database

### Нові таблиці

`faq_topics` — `slug` (унікальний), `sort_order`.
`faq_topic_translations` — `(topic_id, language)` PK, `title`.
`faq_questions` — `topic_id`, `sort_order`.
`faq_question_translations` — `(question_id, language)` PK, `question`, `answer`.

**Контент у базі, а не в бандлі застосунку** — саме цього вимагає FR-004:
контент-команда змінює відповідь без релізу. Та сама причина, з якої
довідники фільтрів є таблицями.

**Порядок зберігається**, бо він редакційний: теми йдуть від норм до
технічних питань, а не за алфавітом, який до того ж різний у кожній мові.

**Питання й відповідь в одному рядку перекладу.** Вони перекладаються разом і
поодинці не мають сенсу; дві таблиці означали б два рядки, які можуть
розійтися мовами.

### Migrations

- `0010_calm_boomer.sql` — чотири таблиці плюс **сім тем і сорок одне
  питання** українською.

**Сід — це копія, яку застосунок уже показує** (`apps/mobile/src/view/user/faq.constants.ts`,
позначена `TODO: replace with the FAQ endpoint`). Контент перенесено, а не
вигадано: вигадувати продуктовий текст замість редакції було б гірше за
порожній екран.

## API contract

### `GET /faq`

**Auth:** `JwtGuard`

```json
{
    "data": [
        {
            "id": "…",
            "slug": "norms",
            "title": "НОРМИ Й РОЗРАХУНКИ",
            "questions": [
                { "id": "…", "question": "Як формується моя денна норма калорій?", "answer": "…" }
            ]
        }
    ]
}
```

**Усе одним запитом, разом із питаннями.** Картки на екрані згорнуті, а не
незавантажені (FR-002); маршрут на тему додав би поїздку на сервер за кожним
тапом по заголовку заради тексту, який уже мав би бути на пристрої.

**`slug` поруч із `id`.** `id` — те, чим рядок ідентифікується, `slug` — те,
чим тему називає аналітика й глибокі посилання. Показувати треба `title`, і
він уже мовою читача.

**Мова — з `user_settings.language`**, з фолбеком на українську, як і всюди в
каталозі. Тема без перекладу в жодній з двох мов не віддається: безіменна
картка гірша за її відсутність.

**Тема без питань віддається порожньою**, а не ховається — це тема, яку
редакція почала й не наповнила, і на екрані вона має бути видимою помилкою,
а не невидимою.

## Security & edge cases

- Контент однаковий для всіх акаунтів; маршрут під `JwtGuard` лише тому, що
  мова читача береться з налаштувань.
- Один запит на весь FAQ: сім тем і сорок одне питання — це кілограм тексту,
  який не вартий пагінації.
- Апострофи в українському тексті («ЗДОРОВʼЯ», «мʼясо») екрановані в сіді
  автоматично: SQL генерувався зі справжньої копії, а не набирався руками.

## Verification

- `apps/client-api/test/notifications.db-spec.ts` — 3 тести FAQ: контент
  приїхав зі схемою, теми й питання в редакційному порядку, фолбек на
  українську для читача з іншою мовою.

## Що ще не побудовано

- **Редагування контенту** — це адмінський сервіс, якого ще немає. Поки
  єдиний спосіб змінити відповідь — міграція.
- **Переклади іншими мовами** — у базі лише українська; фолбек означає, що
  читач будь-якою мовою бачить її.
- **Переходи з відповідей** (відкрите питання специфікації) — текст поки
  простий, без посилань.
