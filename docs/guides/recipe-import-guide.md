# Структура рецептів та імпорт — гайд для редактора

> Як влаштовані продукти й рецепти в каталозі, як підготувати файли для
> масового завантаження і чому система поводиться саме так. Без технічних
> деталей — тільки те, що потрібно, щоб дані доїхали правильно.
>
> Поруч лежить те саме у вигляді веб-сторінки: `recipe-import-guide.html`.

---

## Головна ідея: дві таблиці, суворий порядок

Каталог складається з **продуктів** (інгредієнтів із поживністю) і
**рецептів** (страв, зібраних із цих продуктів). Завантажуються вони двома
файлами, і порядок важливий: **спершу продукти, потім рецепти**.

Рецепт **ніколи не створює продукт сам**. Якщо в рецепті згаданий
інгредієнт, якого немає в каталозі, — цей рядок буде відхилено з
поясненням. Це навмисно: продукт, доданий «на льоту», не мав би поживності,
страва з ним стала б непорахованою, і помилка спливла б цифрою на чиємусь
телефоні за тижні — а так її видно одразу, у звіті імпорту.

---

## Продукт

Продукт — це все їстівне, про що система знає цифри. Його поля:

| Поле | Обов'язкове | Що це |
| --- | --- | --- |
| Назва англійською | так | **Ідентичність продукту.** Саме за нею рецепти знаходять інгредієнт, і саме вона має бути унікальною |
| Назва українською | так | Те, що бачить користувач |
| Калорії, білки, жири, вуглеводи | так | Завжди **на 100 грамів** — єдина цифра, яку система зберігає |
| Група | ні | Молочне, риба, борошняне, фрукти, крупи, м'ясо, солодке, овочі |
| Вага порції, г | ні | Скільки важить одна типова порція |
| Підпис порції | ні | «1 скибочка», «1 ч. л», «1 банка» — двома мовами |
| Швидкий вибір | ні | Чи показувати продукт серед чипсів швидкого вибору у фільтрі |

### Як працює порція

Підпис порції завжди описує **рівно одну** порцію. Кілька порцій — це
множник, а не інший підпис: користувач обирає «3», система рахує
3 × вага порції в грамах, а далі всі цифри — з розрахунку на 100 г.
«3 скибочки» ніде не зберігається. Продукт **без** порції — теж нормальний
стан (гречка, капуста): тоді інтерфейс пропонує лише грами.

### Захист від одруків

Рядок продукту буде відхилено, якщо: калорій більше за 900 на 100 г (це
більше, ніж у чистого жиру, — отже, помилка на порядок), будь-який макрос
більший за 100 г, або білки + жири + вуглеводи разом перевищують 100 г.

## Рецепт

| Поле | Обов'язкове | Що це |
| --- | --- | --- |
| Ключ імпорту | так | **Ідентичність рецепта**: латиницею через дефіс, як `korean-kimbap` |
| Назва українською | так | Українська — основна мова: на неї відкочується все інше |
| Кількість порцій | так | Ціле число |
| Склад | так | Список «продукт: грами» |
| Назва англійською | ні | |
| Категорія | ні | Одна: солоний/солодкий сніданок, обід, вечеря, боули, салати, паста, снеки, десерти, випічка, смузі |
| Кухня | ні | Одна: азійська, грузинська, грецька, італійська, мексиканська, українська |
| Дієти | ні | Скільки завгодно: веган, кето, без глютену, високобілкова… |
| Час приготування | ні | Хвилини |
| Фото | ні | Посилання на зображення |
| Кроки | ні | Українською; англійською — за бажанням, але рівно стільки ж кроків |
| Тривалість кроків | ні | Хвилини по кожному кроку |
| Доступ | ні | **Платний / безкоштовний / невизначено** — див. нижче |

### Ключ імпорту — це пам'ять системи

Повторне завантаження файлу з тим самим ключем **оновлює** страву, а не
створює копію. Тому ключі мають бути стабільними: виправили одрук у назві —
ключ лишається той самий. Двічі один ключ в одному файлі — другий рядок
відхиляється, щоб він тихо не переписав перший.

### Склад: тільки грами, тільки англійські назви

Дві незручності, обидві свідомі:

- **Грами** — бо страва, чиї калорії мають сходитися, не може містити
  «1 склянку». Штуки й ложки автор файлу переводить у грами сам
  (2 листи норі ≈ 6 г, 1 ст. л соку ≈ 15 г) — вага порції в картці
  продукту якраз для цього.
- **Англійська назва** — бо саме вона унікальна в каталозі й однозначно
  вказує на продукт.

Те, що не впливає на калорії — сіль, спеції, «на смак», — у склад не
вноситься взагалі: воно лишається текстом кроку. Діапазони («15–50 г»)
не підтримуються: у файлі має стояти одне число.

### Калорії та БЖВ рецепта не задаються — вони рахуються

Якщо на картці рецепта написано «357 ккал», а система після імпорту
показує інше — це не помилка імпорту. Система **завжди** рахує поживність
страви зі складу. Розбіжність означає, що в якогось продукту зі складу
неправильні цифри — і виправляти треба продукт. Так цифра на картці страви
завжди дорівнює сумі списку інгредієнтів під нею.

## Позначка доступу: три стани

Кожен рецепт каталогу може бути:

| Стан | У файлі | Що означає |
| --- | --- | --- |
| **Платний** | `paid` | Замкнений для користувачів без підписки |
| **Безкоштовний** | `free` | Відкритий усім |
| **Невизначено** | порожня клітинка | Рішення щодо страви ще не ухвалене |

Три важливі нюанси:

1. **Порожньо — це не помилка, а стан.** «Ще не вирішили» відрізняється
   від «вирішили, що безкоштовний», і система їх не плутає.
2. **Одрук не прощається.** Слово, що не є ні `paid`, ні `free`
   (наприклад, `payed`), відхиляє рядок — інакше одрук тихо перетворився б
   на «невизначено», і страва загубила б позначку без сліду.
3. **Повторне завантаження перезаписує позначку.** Файл без колонки
   доступу скине позначки всіх своїх рецептів у «невизначено». Правило
   просте: файл завжди описує страву цілком, як вона має бути.

Позначку так само можна поставити чи змінити прямо в адмін-панелі, у
картці рецепта.

## Переклади

Файл везе дві мови: українську (обов'язкову) та англійську (за бажанням).
Якщо англійські кроки є, їх має бути рівно стільки ж, скільки українських:
переклад, що з'їхав на крок, гірший за відсутній. Третьої мови у файлі не
буде — коли мов стане більше, з'явиться окремий файл перекладів.

## Як відбувається завантаження

1. У панелі: **Products → Import CSV**, потім **Recipes → Import CSV**.
2. Система обробляє файл **порядково**: кожен рецепт зберігається або
   відхиляється окремо. Один поганий рядок не зупиняє інші 499.
3. У відповідь приходить **звіт**: скільки створено, скільки оновлено,
   скільки пропущено — і список помилок, де в кожної вказано **номер
   рядка, який видно в Excel** (заголовок — рядок 1), та зрозуміла причина.
4. Виправляєте відхилені рядки й заливаєте файл ще раз: повторне
   завантаження оновлює вже створене, дублікатів не буде.

Помилка **файлу** (немає обов'язкових колонок, порожній файл) — інша річ:
такий файл відхиляється цілком одразу, без порядкового звіту.

---

## Типові причини відхилення рядка

| Причина | Що зробити |
| --- | --- |
| Немає ключа імпорту або назви українською | Заповнити |
| Порцій нуль або не число | Поставити ціле число ≥ 1 |
| Інгредієнт не знайдено в каталозі | Додати продукт у products.csv і залити його першим |
| Незнайома категорія / кухня / дієта | Звірити зі списками вище — «Сніданок» не категорія, категорія — «солоний сніданок» |
| Англійських кроків не стільки, скільки українських | Вирівняти кількість |
| Тривалостей не стільки, скільки кроків | Вирівняти кількість |
| Той самий ключ двічі в одному файлі | Лишити один рядок |
| У колонці доступу стороннє слово | Тільки `paid`, `free` або порожньо |

## Зразки

У `data/samples/` лежать три готові файли: `products.csv` (15 продуктів),
`recipes.csv` (3 справжні рецепти: сендвіч — безкоштовний, гречка — без
позначки, кімбап — платний) і `recipes-broken.csv` — дев'ять рядків, кожен
зламаний по-своєму, щоб подивитись, як виглядає звіт про помилки.
