# Приклади імпорту

Три файли під **чинний** формат — той, який читає `POST /feedback`-сусід
`POST /api/v1/recipes/import` і `POST /api/v1/products/import` в
`@dns/admin-api`. Не вигаданий: колонки збігаються з
`apps/admin-api/src/modules/recipe/import/csv.parser.ts`.

| Файл | Що це |
| --- | --- |
| `products.csv` | П'ятнадцять продуктів, яких бракує в каталозі для рецептів нижче |
| `recipes.csv` | Три справжні рецепти з карток: сендвіч, зелена гречка, кімбап |
| `recipes-broken.csv` | Вісім рядків, кожен неправильний по-своєму — щоб прочитати звіт |

**Порядок має значення:** спершу продукти, потім рецепти. Імпорт рецептів
**ніколи не створює продукт** — рядок із незнайомим інгредієнтом
відхиляється з поясненням. Це навмисно: продукт без макросів зробив би
страву непорахованою, і помилка спливла б цифрою на чиємусь телефоні за
тижні, а не тут, де її видно у файлі.

```bash
# 1) продукти
curl -X POST https://dev.api.admin.rationfit.com/api/v1/products/import \
     -H "Authorization: Bearer $TOKEN" -F file=@data/samples/products.csv
# 2) рецепти
curl -X POST https://dev.api.admin.rationfit.com/api/v1/recipes/import \
     -H "Authorization: Bearer $TOKEN" -F file=@data/samples/recipes.csv
```

Або через панель: **Recipes → Import CSV** і **Products → Import CSV**.

## Формат: рецепти

| Колонка | Обов'язкова | Приклад |
| --- | --- | --- |
| `import_key` | **так** | `korean-kimbap` |
| `title_uk` | **так** | `Корейський кімбап` |
| `servings` | **так** | `2` |
| `ingredients` | **так** | `White rice:35;Salmon:120` |
| `title_en` | ні | `Korean kimbap` |
| `category` | ні | `lunch` |
| `cuisine` | ні | `asian` |
| `diets` | ні | `pescatarian;high-protein` |
| `cook_time_minutes` | ні | `40` |
| `photo_url` | ні | публічний URL |
| `steps_uk` | ні | `Крок один\|Крок два` |
| `steps_en` | ні | `Step one\|Step two` |
| `step_durations` | ні | `20;12` |

- **`import_key` — це ідентичність рецепта.** Повторний імпорт того самого
  ключа **оновлює** страву, а не створює другу. У рецепта немає іншого
  природного ключа: назви повторюються, а англійська назва — це переклад.
- **Кроки розділяє `|`, списки — `;`.** Якщо `steps_en` є, кроків у ньому
  має бути рівно стільки ж, скільки в `steps_uk`, інакше рядок відхиляється:
  переклад, що зсунувся на крок, гірший за відсутній.
- **`step_durations`** — хвилини по кроках, стільки ж значень, скільки
  кроків.
- **Крок не знає про інгредієнти.** «Крок 2 бере ті самі 250 г помідорів» у
  CSV не висловити, не зробивши другий формат усередині першого; чипси
  інгредієнтів проставляються у формі.

### Інгредієнти

`Англійська назва продукту:грами`, через `;`:

```
White rice:35;Salmon:120;Carrot:50;Nori:6
```

**Тільки грами і тільки англійська назва.** Дві незручності, обидві свідомі:

- Грами — бо страва, чиї макроси мають сходитися, не може містити «1 склянку».
- Англійська — бо саме так продукт адресується в каталозі, і саме англійська
  назва там унікальна.

Так, це означає, що в українському рецепті склад пишеться англійськими
назвами. Якщо це заважає — це виправляється одним рядком в індексі
продуктів (шукати ще й за українською назвою), але тоді дві різні мови
починають конкурувати за один рядок, і дубль «Сир» / «Cheese» стане
можливим. Рішення за вами.

## Формат: продукти

| Колонка | Обов'язкова | Приклад |
| --- | --- | --- |
| `name_en` | **так** | `Nori` |
| `name_uk` | **так** | `Лист Норі` |
| `calories`, `protein`, `fats`, `carbs` | **так** | на 100 г |
| `group` | ні | `vegetables` |
| `serving_weight_g` | ні | `3` |
| `serving_label_uk` / `serving_label_en` | ні | `1 лист` / `1 sheet` |
| `quick_pick` | ні | `true` |

Дедуплікація — за **англійською назвою**. Повторний імпорт оновлює продукт.

Межі, які відхилять рядок: калорії > 900 на 100 г (вище за чистий жир —
отже, помилка на порядок), будь-який макрос > 100 г, сума Б+Ж+В > 100 г.

Наявні `group`: `dairy`, `fish`, `flour`, `fruits`, `grains`, `meat`,
`sweets`, `vegetables`.

## Переклади

Сьогодні формат везе **дві мови**: `title_uk` / `title_en`, `steps_uk` /
`steps_en`. Українська обов'язкова — на неї `coalesce`иться все інше;
англійська необов'язкова.

Третьої мови в цьому файлі не буде, і ширшати він не має. Коли мов стане
більше, правильний крок — **окремий файл перекладів**, а не нові пари
колонок:

```
import_key,language,title,steps
korean-kimbap,pl,Koreański kimbap,Ugotuj ryż…|Usmaż łososia…
```

Причина видно на старому `data/breakfasts.csv` (формат V1, **не
імпортується**): там рядок на кожну мову, і разом із назвою повторюються
калорії, макроси, порції та склад. Тобто одні й ті самі числа лежать у
дев'яти місцях і роз'їдуться з першою ж правкою. Склад і макроси — не
переклад, і жити в перекладі не повинні.

## Що з картки не приїде — і чому

Ваші картки містять три речі, яких формат навмисно не бере:

1. **Готові калорії і БЖВ.** На картці «Калорійність: 357, БЖВ: 28/14/29».
   Система їх **не приймає**: макроси рахуються зі складу
   ([зріз 22](../../HANDOFF.md)). Інакше на картці була б одна цифра, а під
   нею — список інгредієнтів, який дає іншу. Якщо після імпорту число не
   збігається з карткою — розходяться дані продукту, і це видно одразу, а не
   через місяць.
2. **«На смак» і штуки.** «Сіль, орегано — на смак», «2 ч. л (8 г)»,
   «1 ст. л», «Лист Норі — 2 шт». Зберігаються тільки грами, тож:
   - те, що не впливає на макроси (сіль, спеції, цедра), **у склад не
     потрапляє** — воно лишається текстом кроку;
   - штуки й ложки перераховуються у грами автором файлу (2 листи норі ≈ 6 г,
     1 ст. л соку ≈ 15 г). Підказка для інтерфейсу — `serving_weight_g` +
     `serving_label_*` у продукті.
3. **Діапазони.** «Листя салату 15–50 г» — у файлі одне число (взято 30).
   Діапазон не має сенсу для підрахунку: людині все одно доведеться зважити
   одне значення.

Ще одна деталь, помітна саме на ваших картках: **«Сніданок» / «Обід» — це не
категорія в нашому довіднику.** Є `salty-breakfast`, `sweet-breakfast`,
`lunch`, `dinner`, `bowls`, `salads`, `pasta`, `snacks`, `desserts`,
`baking`, `smoothies`. Сендвіч поїхав як `salty-breakfast`, гречка як
`bowls`, кімбап як `lunch`.

## Довідники

- **Категорії:** `baking`, `bowls`, `desserts`, `dinner`, `lunch`, `pasta`,
  `salads`, `salty-breakfast`, `smoothies`, `snacks`, `sweet-breakfast`
- **Кухні:** `asian`, `georgian`, `greek`, `italian`, `mexican`, `ukrainian`
- **Дієти:** `detox`, `gluten-free`, `high-fiber`, `high-protein`, `keto`,
  `lactose-free`, `low-calorie`, `low-carb`, `low-fat`, `pescatarian`,
  `sugar-free`, `vegan`, `vegetarian`

Незнайомий slug відхиляє **рядок**, а не файл, і пише про це у звіті.

## Звіт імпорту

`200` навіть із помилками: частковий успіх — очікуваний результат для файлу,
який набирала людина.

```json
{ "created": 3, "updated": 0, "skipped": 8,
  "errors": [ { "row": 2, "importKey": null, "message": "import_key is required" } ] }
```

`row` — той самий номер, що бачить редактор у Excel (заголовок — рядок 1).
Саме для перевірки звіту існує `recipes-broken.csv`: вісім рядків, вісім
різних причин відмови.
