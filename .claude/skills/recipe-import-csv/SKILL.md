# Створення структури рецептів для імпорту

## Призначення

Ти допомагаєш редактору чи продакт-овнеру перетворити рецепти у будь-якому
вигляді (картки з макетів, текстові описи, таблиці) на два CSV-файли, які
приймає імпорт: спершу `products.csv`, потім `recipes.csv`. Зразки чинного
формату лежать у `data/samples/` — звіряйся з ними, а не з пам'яттю.

## Порядок роботи

1. **Збери склад усіх рецептів** і випиши кожен інгредієнт, що впливає на
   калорії чи БЖВ. Сіль, спеції, цедра — не впливають: вони лишаються
   текстом кроку і в склад не потрапляють.
2. **Звір інгредієнти з каталогом продуктів.** Імпорт рецептів **ніколи не
   створює продукт** — рядок із незнайомим інгредієнтом буде відхилено.
   Все, чого бракує, спершу описується в `products.csv`.
3. **Переведи все в грами.** «2 ч. л», «1 банка», «2 листи норі» — у грами
   (підказка: `serving_weight_g` продукту). Діапазон «15–50 г» — одне
   число, узгоджене з автором. «На смак» — не інгредієнт.
4. **Збери `recipes.csv`**, по рядку на страву.
5. **Прожени контрольний список** (нижче) і віддай обидва файли з коротким
   поясненням, що куди імпортувати.

## Формат: products.csv

| Колонка | Обов'язкова | Правила |
| --- | --- | --- |
| `name_en` | так | Унікальна ідентичність продукту; за нею дедуплікація |
| `name_uk` | так | |
| `calories`, `protein`, `fats`, `carbs` | так | **на 100 г**; калорії ≤ 900, кожен макрос ≤ 100, сума Б+Ж+В ≤ 100 |
| `group` | ні | `dairy`, `fish`, `flour`, `fruits`, `grains`, `meat`, `sweets`, `vegetables` |
| `serving_weight_g` | ні | Скільки важить одна типова порція |
| `serving_label_uk` / `serving_label_en` | ні | Опис **однієї** порції: «1 скибочка», «1 ч. л» |
| `quick_pick` | ні | `true` лише для продуктів-чипсів швидкого вибору |

## Формат: recipes.csv

| Колонка | Обов'язкова | Правила |
| --- | --- | --- |
| `import_key` | так | Ідентичність рецепта: латиниця-через-дефіс (`korean-kimbap`). Повторний імпорт того самого ключа **оновлює** страву |
| `title_uk` | так | Українська обов'язкова — на неї відкочується решта мов |
| `servings` | так | Ціле число > 0 |
| `ingredients` | так | `Англійська назва:грами` через `;`: `White rice:35;Salmon:120` |
| `title_en` | ні | |
| `category` | ні | Один slug: `baking`, `bowls`, `desserts`, `dinner`, `lunch`, `pasta`, `salads`, `salty-breakfast`, `smoothies`, `snacks`, `sweet-breakfast` |
| `cuisine` | ні | Один slug: `asian`, `georgian`, `greek`, `italian`, `mexican`, `ukrainian` |
| `diets` | ні | Через `;`: `detox`, `gluten-free`, `high-fiber`, `high-protein`, `keto`, `lactose-free`, `low-calorie`, `low-carb`, `low-fat`, `pescatarian`, `sugar-free`, `vegan`, `vegetarian` |
| `cook_time_minutes` | ні | Ціле > 0 |
| `photo_url` | ні | Публічний URL |
| `steps_uk` / `steps_en` | ні | Кроки через `\|`; якщо `steps_en` є — кроків у ньому рівно стільки ж |
| `step_durations` | ні | Хвилини через `;`, стільки ж значень, скільки кроків |
| `access` | ні | `paid` (платний) / `free` (безкоштовний) / **порожньо** («невизначено») |

## Нюанси, які найчастіше ламають файл

- **Тільки грами і тільки англійські назви продуктів** у `ingredients` —
  обидва обмеження свідомі, не «полагодити».
- **Готові калорії та БЖВ з картки не беруться.** Система рахує їх зі
  складу. Якщо після імпорту цифра не збіглась із карткою — розходяться
  дані продукту, і виправляти треба продукт, а не вписувати цифру.
- **`access`: порожня клітинка — валідний третій стан «невизначено»**,
  рішення щодо страви ще не ухвалене. Будь-яке інше слово (`payed`,
  `преміум`) відхиляє рядок. Повторний імпорт **перезаписує** позначку:
  рядок без значення скидає страву в «невизначено», а не зберігає старе.
- **Один ключ — один рядок у файлі.** Дубль `import_key` в одному файлі
  відхиляє другий рядок.
- **«Сніданок» і «Обід» — не категорії**: у довіднику `salty-breakfast`,
  `sweet-breakfast`, `lunch` тощо. Незнайомий slug відхиляє рядок.
- Кома, лапки чи перенос рядка всередині тексту — брати клітинку в лапки
  (стандартний CSV; Excel і Google Sheets роблять це самі).

## Контрольний список перед здачею

- [ ] Кожен інгредієнт кожного рецепта існує в каталозі або доданий у `products.csv`
- [ ] Усі кількості — в грамах, без діапазонів і «на смак»
- [ ] `import_key` унікальні всередині файлу і стабільні між версіями
- [ ] `steps_en` і `step_durations` збігаються за кількістю зі `steps_uk`
- [ ] Довідникові slug'и — тільки зі списків вище
- [ ] `access` — лише `paid`, `free` або порожньо
- [ ] Продукти не порушують меж: калорії ≤ 900/100 г, макрос ≤ 100, Б+Ж+В ≤ 100

## Після імпорту

Порядок: спершу `products.csv`, потім `recipes.csv` (через панель:
**Products → Import CSV**, **Recipes → Import CSV**). Звіт повертається
навіть при помилках: `created` / `updated` / `skipped` і список `errors`,
де `row` — номер рядка, який видно в Excel (заголовок — рядок 1). Частковий
успіх — норма: виправляється лише відхилене, і файл заливається ще раз —
повтор оновлює, а не дублює.

Розгорнутий опис для нетехнічного читача: `docs/guides/recipe-import-guide.md`.
