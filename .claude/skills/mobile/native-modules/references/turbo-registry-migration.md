# TurboModuleRegistry & New Architecture Migration

## Quick Reference

| Old Architecture | New Architecture |
|-----------------|-----------------|
| `NativeModules.MyModule` | `TurboModuleRegistry.getEnforcing('MyModule')` |
| Bridge (JSON serialization) | JSI (direct memory) |
| Always async | Sync or async |
| `RCT_EXPORT_MODULE` | Codegen + `getTurboModule` |
| `@ReactModule` | `ReactModule` + TurboModule interface |

## When to Use

- Migrating existing Bridge modules to New Architecture
- Building backward-compatible modules (support both architectures)
- Enabling New Architecture in an existing project

## Step-by-Step Migration

### 1. Enable New Architecture

```bash
# iOS — in Podfile or via env
RCT_NEW_ARCH_ENABLED=1 npx pod-install

# Android — in gradle.properties
newArchEnabled=true

# Expo
npx expo run:ios --configuration Release
# Expo SDK 53+ has New Architecture enabled by default
```

### 2. Create TypeScript Spec (if not exists)

```typescript
// src/NativeMyModule.ts
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  getData(): Promise<string>;
  setConfig(key: string, value: string): void;
}

export default TurboModuleRegistry.getEnforcing<Spec>('MyModule');
```

### 3. Backward-Compatible JS Entry Point

```typescript
// src/index.ts
import { Platform, TurboModuleRegistry } from 'react-native';

// Try TurboModule first, fall back to Bridge
const isTurboModuleEnabled = global.__turboModuleProxy != null;

const MyModule = isTurboModuleEnabled
  ? TurboModuleRegistry.getEnforcing<Spec>('MyModule')
  : require('react-native').NativeModules.MyModule;

export default MyModule;
```

### 4. iOS Migration (Objective-C → Objective-C++)

**Before (Bridge):**
```objc
// MyModule.m
#import <React/RCTBridgeModule.h>

@interface MyModule : NSObject <RCTBridgeModule>
@end

@implementation MyModule

RCT_EXPORT_MODULE()

RCT_EXPORT_METHOD(getData:(RCTPromiseResolveBlock)resolve
                  rejecter:(RCTPromiseRejectBlock)reject) {
  resolve(@"data");
}

@end
```

**After (TurboModule):**
```objc
// MyModule.mm  (note: .mm extension for Objective-C++)
#import "MyModuleSpec.h"  // Generated by Codegen
#import <React/RCTBridgeModule.h>

// Conditional import for backward compatibility
#ifdef RCT_NEW_ARCH_ENABLED
#import <React/RCTTurboModule.h>
#endif

@interface MyModule : NSObject <
  RCTBridgeModule
#ifdef RCT_NEW_ARCH_ENABLED
  , NativeMyModuleSpec  // Codegen-generated protocol
#endif
>
@end

@implementation MyModule

RCT_EXPORT_MODULE()

RCT_EXPORT_METHOD(getData:(RCTPromiseResolveBlock)resolve
                  rejecter:(RCTPromiseRejectBlock)reject) {
  resolve(@"data");
}

RCT_EXPORT_METHOD(setConfig:(NSString *)key value:(NSString *)value) {
  // Implementation
}

#ifdef RCT_NEW_ARCH_ENABLED
- (std::shared_ptr<facebook::react::TurboModule>)getTurboModule:
    (const facebook::react::ObjCTurboModule::InitParams &)params {
  return std::make_shared<facebook::react::NativeMyModuleSpecJSI>(params);
}
#endif

@end
```

### 5. Android Migration (Java/Kotlin)

**Before (Bridge):**
```kotlin
class MyModule(reactContext: ReactApplicationContext) :
  ReactContextBaseJavaModule(reactContext) {

  override fun getName() = "MyModule"

  @ReactMethod
  fun getData(promise: Promise) {
    promise.resolve("data")
  }
}
```

**After (TurboModule):**
```kotlin
// Extend generated NativeMyModuleSpec instead of ReactContextBaseJavaModule
class MyModule(reactContext: ReactApplicationContext) :
  NativeMyModuleSpec(reactContext) {

  override fun getName() = NAME

  override fun getData(promise: Promise) {
    promise.resolve("data")
  }

  override fun setConfig(key: String, value: String) {
    // Implementation
  }

  companion object {
    const val NAME = "MyModule"
  }
}
```

**Package registration:**
```kotlin
class MyModulePackage : TurboReactPackage() {
  override fun getModule(name: String, context: ReactApplicationContext): NativeModule? {
    return if (name == MyModule.NAME) MyModule(context) else null
  }

  override fun getReactModuleInfoProvider(): ReactModuleInfoProvider {
    return ReactModuleInfoProvider {
      mapOf(
        MyModule.NAME to ReactModuleInfo(
          MyModule.NAME,
          MyModule.NAME,
          false, // canOverrideExistingModule
          false, // needsEagerInit
          false, // isCxxModule
          true   // isTurboModule
        )
      )
    }
  }
}
```

## Migration Checklist

- [ ] Create TypeScript spec (`NativeMyModule.ts`)
- [ ] Add `codegenConfig` to `package.json`
- [ ] Rename `.m` to `.mm` (iOS) for C++ support
- [ ] Implement Codegen-generated protocol/interface
- [ ] Add `getTurboModule` method (iOS)
- [ ] Extend `NativeXxxSpec` instead of `ReactContextBaseJavaModule` (Android)
- [ ] Update package registration to `TurboReactPackage` (Android)
- [ ] Add `#ifdef RCT_NEW_ARCH_ENABLED` guards for backward compatibility
- [ ] Test on both Old and New Architecture
- [ ] Run `pod install` and rebuild

## Common Pitfalls

1. **Forgetting .mm extension** — iOS needs Objective-C++ for C++ TurboModule bindings
2. **Missing Codegen run** — Spec changes require `pod install` / Gradle build
3. **Breaking backward compat** — Always guard with `#ifdef RCT_NEW_ARCH_ENABLED`
4. **Java vs Kotlin** — Codegen generates Java interfaces; Kotlin can implement them
5. **Spec drift** — Keep TypeScript spec in sync with native implementation
