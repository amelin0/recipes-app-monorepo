# Shopping list — що реально збудовано (V2)

> `overview.md` поруч описує **V1 на Supabase**. Цей файл описує код, який
> працює зараз: `apps/client-api/src/modules/shopping-list/`.

Реалізовано 2026-09-07. Плани:
[`weekly-list`](../../../docs/specs/client/shopping-list/weekly-list/plan.md),
[`add-product`](../../../docs/specs/client/shopping-list/add-product/plan.md).

## Головне рішення: зберігається половина списку

| | Вручну додане | Імпортоване з плану |
| --- | --- | --- |
| Де живе | рядок у `shopping_list_items` | ніде — сума по плану на читанні |
| Кількість | що вказала людина | Σ складу запланованих страв |
| Можна видалити | так | ні, воно йде за планом |
| Синхронізація | — | не потрібна: нічого не копіювалося |

Саме тому відкрите питання специфікації про «правила синхронізації списку з
планом» відповіді не потребує.

## Схема

```
shopping_list_items     PK (user_id, product_id), amount_g
shopping_list_marks     PK (user_id, product_id, origin), origin = manual|plan
shopping_list_settings  PK user_id, import_from_plan (default true)
```

**Один рядок на продукт** — це і є «жодних дублікатів» зі SC-003: повторне
додавання сумується через `ON CONFLICT`.

**Відмітки окремо від позицій**, бо в імпортованого рядка немає рядка.
Наявність відмітки і є станом; незнята галочка — відсутність рядка.

**Ключ відмітки включає походження**: той самий продукт може стояти двічі —
раз із плану, раз руками, — і купівля одного не гасить інший.

## `product_groups` тепер обслуговує два екрани

| Стовпчик              | Хто читає            |
| --------------------- | -------------------- |
| `sort_order`          | фільтр рецептів      |
| `shopping_sort_order` | список покупок       |
| `is_recipe_filter`    | фільтр показує лише `true` |

Груп вісім: до шести фільтрових додано `flour` «Мучні» і `grains` «Крупи» —
полиці магазину, за якими рецепт ніхто не фільтрує. Порядки різні: фільтр
починає з овочів, список — із мʼясного.

Продукт без групи потрапляє у хвостову групу `group: null` — це «Інше», а не
рядок довідника з такою назвою.

## Одиниці

Кількість приходить одиницею й числом, конвертується на сервері:

| Одиниця | Межі      | У грамах |
| ------- | --------- | -------- |
| serving | 0,5–20    | 250      |
| piece   | 1–100     | 100      |
| gram    | 50–10 000 | 1        |

Числа в `SHOPPING_UNIT_LIMITS` / `SHOPPING_UNIT_GRAMS`. Конвертація на
сервері — це те, що дозволить зробити еквіваленти пер-продуктними
(`products.serving_weight_g` уже є) без релізу застосунку.

Значення понад максимум **відхиляється**, а не обрізається: тихо змінити
введене число гірше за відмову.

## Чого ще немає

- Обʼємні продукти (мл) — потребують одиниці на продукті; склад рецепта теж
  лише в грамах (ADR-0006).
- Редагування кількості вже доданої позиції.
- Автоматичне очищення списку: він не чиститься сам ніколи, лише явно.
